# Architecture: the classical sorter and its submission image

Technical reference for teammates and judges. It describes the code as it is at this tree (rc6 worktree, base `a343a00`).
Every claim points at a file or flag. Where this doc and the code disagree, the code wins.
The flag table in section 4 is generated by `tools/gen_flag_table.py`; regenerate it instead of editing it.

## 1. Overview

Two processes. The **runner** (`aaltonomous/deploy/runner.py`) owns the robot or sim, the `SafetyFilter`
(`aaltonomous/interface/safety.py`) and the 30 Hz loop. Every command goes through the filter. The **policy container**
is this image: a websocket + msgpack server on port 8000 (`aaltonomous/deploy/policy_server.py`, `protocol.py`). It
gets observations and returns joint targets. It never talks to the robot.

```
runner (30 Hz, SafetyFilter)                       policy container (tools/submission.Dockerfile, :8000)
  obs: head_rgb, head_depth, arm_q, hand_q,  --->  ClassicalServerPolicy  (baselines/classical/policy_server.py)
       instruction, t                                -> ClassicalPolicy     (baselines/classical/policy.py)
  arm_q_target, hand_q_target chunk          <---
  -> SafetyFilter clamps, then robot / sim
```

Stages inside `ClassicalPolicy`, in call order:

1. **Instruction** (`reset`, once per episode). `policy._instruction_mapping` runs:
   `normalize.normalize` (typo/synonym fixes, flag `instruction.normalize`) -> `instruction.resolve` (the frozen resolver,
   per the header of `normalize.py`) -> one of two endings. With `instruction.strict` the result goes through
   `normalize.strict_mapping`, which abstains instead of guessing and has no fallback. Otherwise unparsed keys fall back to
   `policy.fixed_mapping` (null = sim `FIXED_MAPPING` from `interface/tasks.py`). `instruction.max_chars` caps long text
   first. `policy.insert_guard` overrides everything for the insert task (abstain on every object).
2. **Perception** (`perception.py`, `Perception.detect`). HSV colour masks (`perception.hsv_set`: stock | robust | robust_v2),
   depth to pelvis-frame positions, shape from the top face (`classify_shape`, `shape_id.py`), blob splitting
   (`split_blobs`), red/yellow hue abstain (`hue_guard`, `hue_guard.py`), and the post-filter `color_gate` (area, workspace,
   bin footprint, FK arm mask). Calibration runs per episode: pitch from the counter plane or the orange bin rims
   (`calibrate_pitch`, `online_pitch_cal`), counter height (`update_counter_height`, `calib.plane.apply_height`), bin
   position votes (`calibrate_bins`, `bin.vote.enabled`), and the arm-based head-pose refinement in `hand_calib.py`.
3. **Decision** (`policy._choose`, `_choose_retry`, `_ordered_cands`). Pick the next object. `lookup_bin` maps colour, or
   (colour, shape) with `policy.bin_lookup: resolve_bin`, to a bin. `None` means do not pick. `decision.py` holds the D1-D4
   tiers and isolated-first ordering, all default off. Retry logic (`retry_vary_grasp`, `max_attempts`) lives here too.
   `brain/` is an optional closed-set tool chooser. It is off in both overlays (`brain.enabled: false`, `brain.backend: stub`).
4. **Planning** (`planner.py`, `Planner.plan` / `plan_to_counter`). Grasp variants and drop slots. Arm IK is in
   `kinematics.py` (`ArmKinematics`: FK of the palm grasp point plus damped least-squares IK, Pinocchio on the G1 URDF).
5. **Motion** (`planner.py`: `time_scale`, `ramp`). Trajectories are time-scaled to `motion.arm_max_vel` and `arm_max_acc`.
   `motion.arm_vel_cap` lowers them further (`config._apply_arm_vel_cap`, never faster than the profile). The planner returns
   chunks of `motion.chunk` ticks.
6. **Safety** (section 3): `safety.nan_guard`, `policy.safety_shell` (`safety_shell.py`, `policy._act_shell`), then the
   runner's `SafetyFilter` as the last word.

Config is `config.yaml` + the `sim` profile (`profile:` key) + an overlay. The overlay is `overlays/<name>.yaml`, chosen by
argument, then `$AALTO_OVERLAY`, then the baked `overlay.yaml`. Only keys in `config.FLAGS` are accepted.

## 2. Threading model

- `ClassicalServerPolicy` builds `ClassicalPolicy(threaded=True, require_confirm=False)`. This is the only mode the
  policy server runs. `sys.setswitchinterval` drops to 1 ms in this mode so Python planning yields the GIL quickly.
- **`act()` must never block.** When threaded, a look (perception plus planning) runs in a daemon thread started from
  `_act` (`policy.py`, `_look_job`). While it runs, `_act` returns `_hold()`: `motion.hold_ticks` (6) repeats of the last
  target. The next `act()` picks up the finished result.
- Pitch and hand calibration run through `_bg` (`policy.py`, around line 553). It starts a low-priority thread and returns
  `None` until the result is ready. `act()` polls it and never joins.
- `policy.safety_shell` (`_act_shell`) wraps `_act`. An exception, or a call over the budget (`safety.hold_after_s`, 0.2 s),
  becomes a hold of the last target. The chunk popped for the discarded answer goes back on the queue, and `act()` never raises.
- One exception to "never blocks": `ClassicalServerPolicy.reset` waits up to 30 s for a running look thread
  (`policy_server.py`). It runs between episodes, not in `act()`.
- Non-threaded mode (`threaded=False`, used by `sim_eval.py` and `tools/equivalence_check.py`) runs `_look` inline.
  That is why the equivalence digest is deterministic.

## 3. Safety guarantees

Each row names the code or flag that enforces it. The last two columns give the state in the two overlays. The baked image
runs `overlays/submission.yaml`. `finals_r21` is the candidate for the finals.

| # | Guarantee | Enforced by | finals_r21 | submission (baked) |
|---|---|---|---|---|
| G1 | Per-tick command change is bounded. Each joint moves at most `arm_max_vel * dt` / `hand_max_vel * dt` from the last command, not the measured pose. | `interface/safety.py` `SafetyFilter` (defaults 1.0 / 3.0 rad/s; `config.yaml` sim profile sets `arm_max_vel` 0.97, `hand_max_vel` 2.5). Always on. | always on | always on |
| G1b | The planner never plans faster than a chosen cap. | `motion.arm_vel_cap` (`config._apply_arm_vel_cap`: must be in (0, 1]; lowers `arm_max_vel` and scales `arm_max_acc`). | 0.90 | null (profile value) |
| G2 | Non-finite joint values never reach the filter or the planner. In `act()`, a NaN or inf in `arm_q` or `hand_q` skips the planner and holds the last emitted action. Before any action, it holds measured-or-home. Non-finite depth becomes 0 (missing). | `policy._nan_guard` (flag `safety.nan_guard`). The filter also validates: a bad part holds its last command (`safety.py`, "validate"). | on | **off** |
| G3 | An exception or a deadline miss in `act()` holds the last target. `act()` does not raise. | `policy._act_shell` (flag `policy.safety_shell`). The filter also does this: `hold_after_s` 0.2 s marks the command stale, `stop_after_s` 1.0 s gives a latched safe stop. | on | **off** |
| G3b | Plans are stretched so that a 20 % velocity reserve is left under the filter limit. | `policy.safety_shell_vel_reserve` (`safety_shell.py`). Default 0.0 means plans are untouched, despite the 20 % in the module docstring. | 0.0 (unset) | 0.0 |
| G4 | No guessed bin. Text that does not parse abstains, so the object stays on the counter: 0 points, never -1. | `policy.insert_guard` (abstain on the insert task); `policy.bin_lookup: resolve_bin` (`planner.lookup_bin`: `None` or "abstain" means no pick, `policy.py` "never a -1 guess"); `instruction.strict` (`normalize.strict_mapping`: unparsed text abstains every key). | strict on, insert_guard on | strict **off**, insert_guard on |
| G5 | Long instruction text cannot blow the resolver's time (it is quadratic: 50k chars took 19 s). The text is cut at the last sentence or clause boundary. | `instruction.max_chars` (`policy._cap_text`). | 2000 | **0 (off)** |
| G6 | Red and yellow hues too close to tell apart: both abstain, so no swapped bin. | `perception.hue_guard.enabled` (`hue_guard.py`). | on | **off** |
| G7 | Arm and hand poses outside the workspace box are refused, and wrist/palm frames stay out of the counter keep-out box. | `SafetyFilter` workspace check (`SafetyConfig.workspace`, default True; `counter_keepout_*`). | on | on |
| G8 | Real-robot colour to bin mapping, used when the instruction gives none. Yellow goes left, blue class (purple objects) centre, red class (orange objects) right. | `policy.fixed_mapping: {yellow: left, blue: center, red: right}`. Null falls back to the sim mapping in `interface/tasks.py` (`red: left, yellow: center, blue: right`). | real-robot map | **null, so the sim map** |
| G9 | Hard cap on started picks per episode. | `policy.max_total_attempts` (finals 18). | 18 | null |

Two consequences of the table, for whoever changes the overlay:

- The baked `submission.yaml` does not carry the safety switches that `finals_r21` turns on (G2, G3, G5, G6, and the strict
  abstain in G4). The fixed mapping in G8 is also the sim one. `tools/release_gate.py finals_r21` currently prints
  `RELEASE GATE FAIL` with 22 differing flags. Promoting an overlay with `tools/promote.sh` is how these get synced.
- The 20 % reserve in `safety_shell.py` and `test_safety_shell.py` is only active when
  `policy.safety_shell_vel_reserve` is above 0. Both overlays leave it at 0.

## 5. How to run

The image is built from `tools/submission.Dockerfile` with the repo root as the build context. The Dockerfile header and
`tools/wendy/README.md` give these commands:

```bash
docker build -f tools/submission.Dockerfile -t hackjunction/policy:<tag> .      # from the repo root
docker run --rm -p 8001:8000 hackjunction/policy:<tag>                          # add --gpus all on the GPU box
docker run -d --gpus all -p <port>:8000 <image>                                  # organisers' form, no args or env
python -m aaltonomous.deploy.replay --synthetic 100 --policy ws://localhost:8001   # dry run: shapes, command rate
docker run --rm --entrypoint python3 hackjunction/policy:<tag> tools/flags.py    # which flags are baked in
```

The image runs `python3 -m aaltonomous.baselines.classical.policy_server`, which listens on `PORT` (default 8000).
The build fails if the config, overlay, URDF or calibration do not load, or if a posture is outside the URDF limits
(Dockerfile `RUN` checks). Only the overlay file in `overlays/` decides the flags, so rebuild after any edit.

Other run modes, from `aaltonomous/deploy/README.md` (image and team names are placeholders here):

```bash
python -m aaltonomous.deploy.policy_server                                       # example hold policy on :8000
python -m aaltonomous.deploy.runner --backend mock --policy ws://localhost:8000 --team demo --episodes 2
python -m aaltonomous.deploy.runner --backend sim --container <image> --team <team> --episodes 5 --video --export
```

Wendy (`tools/wendy/README.md`). Nothing here has been run on venue hardware, and the README marks several steps as
unverified. Wendy reads `wendy.json`, and `--dockerfile` must be a bare filename in the project directory:

```bash
cd <repo-root>
ln -sfn tools/wendy/wendy.json wendy.json
ln -sfn tools/submission.Dockerfile Dockerfile
wendy discover --type lan --timeout 5s
wendy run --device <address-from-discover> --build-type docker --dockerfile Dockerfile \
  --skip-cloud-registration --chunking force --wait-ready
```

Environment variables read by the policy server (`policy_server.py` docstring): `AALTO_TIME_LIMIT` (default 120 s, must
match the runner's `--time-limit`), `AALTO_ARM_VEL` (overrides `arm_max_vel`), `AALTO_PROFILE` (default `sim`; `none` for
the robot base values), `AALTO_OVERLAY` (A/B overlay by name, for example `AALTO_OVERLAY=rc1`), `PORT`.

Naming: `aaltonomous/deploy/README.md` and `QUICKSTART.md` point at `docker/submission.Dockerfile`, which is the generic
participant template under `aaltonomous/docker/`. The image this doc describes, and the one the Wendy manifest builds, is
`tools/submission.Dockerfile`.

## 6. Testing

- Unit tests for the classical policy and the flags (no GPU). The command is `unittest discover`:
  ```bash
  python -m unittest discover -s aaltonomous/baselines/classical -p 'test_*.py' -t .
  ```
  Shared interface and scene tests, from the root README:
  `python -m unittest aaltonomous/interface/test_safety.py aaltonomous/interface/test_env.py aaltonomous/scene/test_scene.py`.
  Deploy tests: `python -m unittest aaltonomous/deploy/test_deploy.py` (set `AALTO_TEST_IMAGE=<image>` for the Docker test).
- Equivalence: `tools/equivalence_check.py` digests every returned action and event of seeded mock episodes plus a
  perception digest. It runs non-threaded, so it is deterministic. The diff is the verdict:
  ```bash
  PYTHONPATH=<baseline tree>    python tools/equivalence_check.py > base.txt
  PYTHONPATH=<integration tree> python tools/equivalence_check.py > integ.txt
  diff base.txt integ.txt && echo IDENTICAL
  ```
  `promote.sh` runs it with `AALTO_OVERLAY=submission`. Flags-off equivalence means the baseline behaviour is unchanged.
- Release gate: `python3 tools/release_gate.py <rc>` exits 0 (PASS) only if `overlays/submission.yaml` carries exactly the
  flags of `<rc>`. `test_release_gate.py` covers it. `python3 tools/flags.py --expect-off` is the baseline-image guard.
- Fuzz: `test_fuzz_inputs.py` (non-finite and absurd inputs, `max_chars` and `nan_guard`). Safety shell:
  `test_safety_shell.py` (deadline miss, exception on the first call).
- `tools/promote.sh <overlay>` is the release path: 7 steps, writes `overlays/submission.yaml`, `RELEASE.md`,
  `RELEASE.flags.json` and `RELEASE.equivalence.txt`, commits nothing. Use `--dry-run` to rehearse it.
